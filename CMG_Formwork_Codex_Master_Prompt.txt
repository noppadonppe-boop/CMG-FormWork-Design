Act as a senior structural software engineer. Build a multi-project platform for importing drawings, interpreting and confirming concrete geometry, proposing and checking plywood-faced formwork for rectangular and supported nonrectangular footings/columns, including L-shaped sections. The platform must produce a traceable classical engineering calculation report and dimensioned assembly/installation drawings from the same confirmed model and calculation snapshot.
Build deterministic engineering software. An LLM must not calculate authoritative design results, invent material strengths or issue engineering approvals.
First inspect the selected workspace, existing files, package manifests, runtime versions and applicable AGENTS.md. Preserve unrelated files. Do not assume access to any previously mentioned Windows path.
If the selected workspace is unrelated, do not modify that repository; propose a separate project directory. If it is empty, initialize a new project there.
Complete local implementation, documentation and automated tests sequentially by phase. Do not stop merely to ask approval for ordinary reversible coding decisions. Record noncritical assumptions. Missing engineering inputs must block the affected design checks, not the whole software-development task.
Do not deploy to production, create paid cloud resources, change billing, use real project data, expose credentials, make Git commits/pushes, or connect engineering software unless explicitly authorized.
Use Firebase Emulator Suite with a demo project ID by default. Production connection must be an explicit, visibly separate configuration.
Report genuine completed functionality, limitations and test evidence. A successful build is not engineering validation or permission for construction.

2. SCOPE, SYSTEM TYPES AND CAPABILITY BOUNDARIES
Implement two distinct formwork systems:
A. FOOTING_THROUGH_TIE:
Fresh concrete pressure → plywood → vertical studs → double walers → bearing plates/nuts → through-ties connecting opposite faces.
Footing base transfers concrete gravity load to the supporting foundation/ground; do not automatically apply concrete weight to side walers.
B. COLUMN_EXTERNAL_YOKE:
Fresh concrete pressure → plywood → vertical studs → external yokes/segmented frames → external corner clamps/connections; rectangular cases use four-sided yokes, polygon cases require their own validated topology.
Do not treat a column external corner rod as a through-tie. Do not size it from p × tributary area or divide a face reaction by two without a validated connection model.
A column using actual through-ties is a separate explicitly selected system, with rebar/cover/penetration checks.
Never interchange these systems silently.

Initial validated geometry must include rectangles/squares and constant-height/depth L-shaped orthogonal polygons with flat plywood faces. Other polygon families and their engineering capabilities follow section2C.
Single-sided forms, climbing/slip forms, circular/tapered columns, inclined forms, curved geometry, top/soffit forms and complex cantilever systems require explicit separate methods. Retain identifiable unsupported source geometry as a draft and block affected engineering checks; never silently replace it with a rectangle.
Do not create fictitious construction joints to reduce pressure. A phased pour requires the permanent-structure designer's accepted construction-joint location and an actual pour/set-time plan.
Separate each method's capability: implemented, independently validated, evidence-complete, eligible for project use.
A calculation method not yet validated must return UNSUPPORTED or INCOMPLETE for the required check. Do not replace it with zero force or a generic safety margin.

2A. FIRST STEP: DRAWING/PDF/SKETCH IMPORT AND AI ASSISTANCE
The user may begin by uploading a PDF drawing, scanned PDF, photograph of a dimensioned sketch, or PNG/JPEG image instead of typing dimensions.
Provide a real Upload Drawing / AI Analysis menu within each project/case.
Use PDF.js or an equivalent verified parser to display selected pages and extract available vector text. Combine selected page images with text for visual analysis; OCR text alone may miss dimensions and drawing relationships.
Accept multiple relevant views/pages for the same object: plan, sections and elevations. User selects the intended object/type and source revision; do not merge unrelated footings or columns.
Preserve the original source with immutable content hash, filename, drawing/page/revision metadata and project-scoped access. Page rotations/crops are derived artifacts with recorded transforms, not replacements for the source.
Scans and photographs must have an editable crop/rotate/deskew workflow; display image-quality/readability warnings.
No pixel measurement or depicted proportions become a confirmed construction dimension automatically.
Explicit dimension labels outrank page scale or visual appearance; conflicting dimension labels still require user resolution.
An image may provide plan dimensions without footing depth or column height; request/allow manual entry of the missing dimension.
A perspective photograph cannot use one planar scale to recover all 3D dimensions. Preserve UNKNOWN where evidence is insufficient.
Model extraction must locate the CONCRETE boundary, not accidentally the outer form, reinforcement cover, gridline or dimension-line rectangle.
Distinguish dimensions describing permanent concrete from proposed formwork sizes.
Do not execute embedded PDF actions/scripts or fetch external drawing links automatically.

Import workflow:
SOURCE_UPLOADED → AI_EXTRACTION_DRAFT → GEOMETRY_NEEDS_CONFIRMATION →
GEOMETRY_CONFIRMED → PRELIMINARY_LAYOUT_PROPOSED → LAYOUT_SELECTED →
DETERMINISTIC_CALCULATION → ENGINEERING_REVIEW → DOCUMENT_ISSUE.
These are ingestion/layout events distinct from the engineering/workflow states in section14.
Users may also enter/draw geometry manually and bypass AI while following the same geometry-validation/confirmation contract.
AI helps interpret geometry and explain options. It cannot confirm dimensions, approve a design, certify material or write a trusted calculation.

2B. DIMENSION EXTRACTION, EVIDENCE AND HUMAN CONFIRMATION
Produce schema-validated extraction results, not free text alone.
Each extracted dimension records:
dimensionId, target entity/edge, dimension type, original text/value/unit,
normalized value/unit or null, source artifact hash, page index,
bounding box/pixel coordinate system and transforms,
origin EXPLICIT_DIMENSION / DERIVED_CONSTRAINT / SCALE_MEASURED /
AI_INFERRED / USER_ENTERED, extraction confidence/readability,
conflict/unknown flags, confirmation status, confirmedBy/At and override reason.
Confidence is a review aid, not a calibrated probability or a permission to auto-confirm.
Infer geometry relationships tentatively; do not guess missing critical dimensions just to close the polygon.
A derived dimension is allowed only from an explicit consistent constraint equation, with derivation shown and user confirmation. It is not a fabricated dimension.
Keep geometry coordinates separate from dimensional constraints; solve constraints deterministically and detect inconsistency/underdetermination.
Handle mm/cm/m, decimal separators, feet/inches when explicitly present, handwritten Thai/English labels, rotations, repeated dimensions and differing drawing revisions.
Unknown depth/height, unresolved critical units, incompatible dimensions or ambiguous target object prevent geometry confirmation.
Provide a split view: source page on one side, geometry overlay and dimension table on the other. Clicking an edge/dimension highlights its original evidence.
User can edit vertices, dimensions, height/depth, axes/origin, object identity and boundary classification.
Every override preserves old extraction data, actor, timestamp and reason.
Allow a saveable draft when inputs are incomplete. Never convert null to zero.
Confirm Geometry creates an immutable normalized geometry revision/hash linked to the exact sources and resolution record.
Geometry confirmation verifies interpreted input; it is NOT engineering approval.
Changing the source selection/revision, geometry, units or unresolved constraint invalidates current proposals/calculation freshness and creates a new revision. A completed AI job on old inputs cannot overwrite the current draft.

2C. NONRECTANGULAR FOOTINGS/COLUMNS — FIRST-CLASS GEOMETRY
Required first supported geometric families:
- Rectangle/square.
- L-shaped orthogonal simple polygon.
- T-shaped/U-shaped and other orthogonal simple polygons where all engineering load paths are supported.
- Other straight-edged simple convex/concave polygons as explicit geometry/import/rendering entities; complete engineering eligibility depends on validated edge/corner/tie methods.
- Circular/curved outlines, internal voids, sloping/stepped heights, tapers and compound sections can be identified/retained as draft geometry, but require separately implemented analysis methods. Do not silently convert them into a rectangle or approximate them for issued design.

Geometry contract:
type FOOTING/COLUMN; local datum/axes; outer ring of vertices with IDs;
directed edges/face IDs, edge lengths and inward/outward normals;
convex/re-entrant corners with corner IDs/angles;
constant footing depth or constant column extrusion height for initial supported calculations;
optional holes/step/curve descriptors with explicit capability status;
dimension constraints/evidence; revision/hash and units.
Rendering a shape successfully does not mean its structural system is calculated.
Require closed non-self-intersecting boundaries, no zero/duplicate edges, positive area,
consistent orientation/units, stated geometric tolerances and verified dimensional closure.
Compute area, perimeter, centroid and face normals deterministically. Use robust polygon offset/join algorithms for outside formwork, studs and walers; naive concave offsets can overlap/invert members. Reject or explicitly resolve such collisions.
Do not automatically snap a nearly orthogonal edge to90 degrees without showing and confirming the change.
Reject bow-tie polygons, impossible dimensions, negative arm widths, overlapping boundaries and unstable constraint solutions.
For a polygon with unsupported holes/height transitions, do not ignore hole walls or unmodelled pressure faces; whole-system eligibility remains blocked.
Do not approximate an L-shaped object by its bounding rectangle.
If decomposing into analysis zones or panels, the OUTER concrete boundary remains authoritative. Internal partition lines are not formwork walls, construction joints or new load supports.
Avoid duplicate pressure loads, duplicate corner members and overlapping MTO when two rectangular zones meet.

Per-edge analysis:
Assign every exposed side face its own local coordinates, vertical/horizontal supports, pressure, member orientation, waler chain, connections and reaction mapping.
Hydrostatic pressure depends on local depth below the actual current free surface, not plan shape.
Global X/Y directions alone are insufficient for a general inclined edge; use local face coordinates and transform forces correctly.
Trace every face's pressure resultant/moment through a supported load path. No omitted concave/notch faces.
Convex and concave corners have distinct actual connection details; pressure on notch faces must use the correct normal/sign.
For nonconstant heights or inclined side faces, use a separately validated method; do not stretch the constant-extrusion equations.

Tie routes:
Define each through-tie by start/end face IDs, actual endpoints, sleeve envelope,
rod path/length, load direction, end connection/waler supports and offsets.
Check that the internal through-tie route remains within the intended concrete volume and connects compatible support faces. An external gap crossed by a route is not an internal concrete sleeve.
For L/U shapes, do not pair faces only because their bounding-box coordinates oppose.
Initial automatic tie generation is limited to parallel opposed support faces with perpendicular rods. Angled/non-opposing configurations require their own validated vector/joint method and cannot be silently generated as eligible designs.
Flag missing opposed faces, a rod exiting/re-entering the footprint, inadequate concrete clearance,
tie/tie clashes, rebar conflicts and inaccessible end nuts.
A diagonal tie produces force components; it must not be analysed using an orthogonal axial shortcut.
If a region needs one-sided bracing, external framing or a special corner tie arrangement, identify it and require its verified separate system model.
For nonrectangular columns, a rectangular four-corner yoke cannot simply be stretched onto an L-shaped perimeter. Require a supported polygonal yoke/segmented-frame connection topology or certified equivalent.
Unsupported re-entrant-corner/yoke/tie regions still allow preliminary drawings and supported component demands, but block whole-system PASS and construction issue.
An L-shaped case must be a real geometry/UI/test fixture in this release, not a decorative drawing that silently calculates a rectangle.

2D. AI PRELIMINARY LAYOUT BEFORE DETAILED CALCULATION
After geometry confirmation, AI explains a preliminary arrangement and offers up to3 coherent candidate layouts.
Inputs to the proposal:
confirmed geometry, face/corner IDs, desired surface quality, concrete/pour information,
project criteria, actual available plywood/Thai steel/rod/brace catalogs,
assembly preference, stock/panel sizes, handling limits and installation access.
If concrete/pour data are missing, retain a planning-only proposal with listed unknowns. Do not fabricate a design pressure.
AI can recommend a preliminary plywood thickness from available thicknesses,
stud section/orientation/spacing per face, double RHS/C waler section/orientation/levels,
through-tie diameter/system and actual spacing/routes,
column yoke/corner arrangement, panel joints, braces/anchors and access provisions.
No model-generated material strength, equipment capacity or market price.
Every suggested section/equipment ID must resolve to an allowed catalog revision. If no verified catalog is available, identify candidate needs rather than invent product ratings.
Recommendations need explanation: load path, lower-pressure/higher-pressure zones,
concave corners, panel widths/joints, available stock, assembly simplicity and access.
AI may explain or rank candidates but geometry placement and spacing generation must be deterministic, dimensioned and reproducible.
Run lightweight deterministic applicability/geometry screening before presenting a candidate. Any numerical engineering pre-check must show method/inputs and be labelled screening, not full system approval.
Distinguish AI draft, geometrically feasible layout, numerically screened layout and fully checked calculation.
Initial suggestions are marked PRELIMINARY_UNCHECKED / FOR REVIEW.
Show candidate comparison: plywood thickness, stud/waler sections,
requested and actual spacing, tie/yoke/brace counts, preliminary MTO,
known limitations/uncalculated connections and why each option was suggested.
Support user editing of every layout position/section before detailed calculation.
Selecting a proposal freezes a versioned layout tied to geometry/criteria/catalog revisions; it does not approve engineering safety.
Then run the authoritative full calculation in sections7–9.
If checks fail, return clearly identified members/corners/connections to revision.
AI may explain failures and suggest catalog-bound alternatives; all alternatives must be recomputed by the deterministic engine.
Bound iteration/search count, prevent an infinite suggest/recalculate loop, and display NO_FEASIBLE_LAYOUT honestly.

3. ENGINEERING DESIGN BASIS AND SOURCE REGISTRY
Use SI consistently. Recommended internal solver units:
length mm; force N; stress MPa = N/mm²; moment N·mm; I mm⁴; S/Z mm³.
Pressure input/display kPa or kN/m² must convert explicitly: 1 kPa = 0.001 N/mm².
Pressure engine may use m, kN and kPa internally only with typed conversion boundaries.
Display optional kgf/cm² with 1 kgf/cm² = 0.0980665 MPa; never treat kg as force.
Do not round intermediate values for checking; round only for report display.

Standards registry:
- Standard title, edition/reapproval, jurisdiction, exact clause/equation/table, verified source URL or user-owned reference document, retrieval date, applicability and reviewer verification.
- Distinguish a guide, a product standard, a structural-design specification, and a project-specific criterion.
- Proposed references: ACI PRC-347-14(21) for formwork guidance/loads/accessory safety; appropriate AISC 360 edition for applicable structural steel/HSS; appropriate AISI S100 edition for applicable thin-walled cold-formed members; APA V345/Y510 or certified manufacturer data for plywood; applicable Thai material standards/project specifications.
- Do not claim blanket compliance with all standards or Thai regulations.
- A web excerpt is not a complete implementation source for an entire standard.
- Obtain authorized full references where needed. Do not fabricate clause numbers or reproduce standards wholesale.
- Separate ASD and LRFD. Implement ASD first with one documented load/capacity basis. Hide or disable LRFD until actually implemented and validated.
- No general 0.6Fy override can replace local/global buckling and connection checks.
- Criteria changes create a new revision; existing calculation snapshots retain their old criteria.

Formula record:
formulaId, version, expression/LaTeX, description, variables with units,
sourceId, exact sourceLocator, assumptions, applicability predicates,
loadBasis, resistanceBasis, validationFixtureIds and methodVerificationStatus.
Calculated step:
stepId, formulaId/version, componentId, loadCaseId, inputs,
symbolic formula, substitution, unrounded result, display result, units,
acceptanceLimit, utilization, checkStatus, assumptions and source reference.
Use the same step objects in UI and reports; no separate formulas in React components.
Snapshot must embed actual normalized input/material/criteria values and provenance, not only catalog IDs. Capture engine/formula/schema versions and canonical numeric payload. Content hashes show integrity, not a professional signature.

4. DESIGN CRITERIA UI
Create a real criteria editor with immutable revisions:
- Pressure method, concrete unit weight, placement rate, concrete temperature, slump/SCC, admixtures, cement/mix coefficients, vibration type/depth and pour direction.
- Load cases and combinations; wind basis/input, work platform/equipment loads and erection conditions.
- ASD safety factors by failure mode; accessory minimum ultimate-strength factors separately.
- Plywood bending/rolling-shear/bearing criteria and stiffness basis.
- Steel yielding, local/global buckling, shear, bearing/crippling and connection method.
- Deflection limits per component and total face movement, out-of-plumb tolerance.
- Material source/evidence requirements and whether project-verified data are permitted.
- Optimization constraints: permitted stock sizes, minimum/maximum spacing, edge distances, actual support coordinates, overhangs, target utilization and tie clearance.
- A proposal such as L/360 must be labelled project criterion, not universal code requirement.
- No hidden defaults that can turn unknown inputs into a construction PASS.
All numeric inputs need units, valid ranges and help. Unknown ≠ zero.

5. MATERIAL, SECTION AND EQUIPMENT CATALOGS
Evidence metadata for every record:
manufacturer/product/standard/grade, source reference, document attachment,
tested/design value type, wet/dry state where relevant, units,
verifiedBy, verifiedAt, revision, validity scope and status:
DEMO_ONLY / UNVERIFIED / PROJECT_VERIFIED / MANUFACTURER_VERIFIED.
Demo values cannot support an issued-for-construction report.

5.1 Plywood
Store actual/minimum thickness, layer arrangement/grade, strength direction,
wet allowable bending in both directions, rolling shear/bearing,
effective section modulus or directly certified bending capacity,
EI in both directions, shear stiffness or compatible shear-deformation method,
duration/moisture adjustments and whether already included.
MOR/test failure strength is not allowable stress.
Do not pair APA Fb with gross homogeneous bt²/6 automatically.
Use properties and equations from one compatible design system.
Do not apply wet/load-duration/concrete-setting adjustments twice.
Face-film/WBP marketing labels alone do not verify structural capacity.
Keep reuse/condition exclusions: delamination, swelling, damaged edges/holes.
Support discrete catalog thickness choices and checking a user-entered thickness with verified compatible properties.

5.2 Thai RHS/SHS and channels
Store actual/design wall thickness, B/H/lip/radius dimensions, material Fy/Fu/E,
A, Ix/Iy, Sx/Sy, Zx/Zy, rx/ry, torsional properties where required,
local slenderness, source and design-method applicability.
Distinguish structural HSS, hot-rolled C/channel, cold-formed lipped C and unverified light commercial sections.
"Light grade" is not a material strength designation.
Do not classify a section by wall thickness alone or assume all cold-formed HSS must use AISI.
Use product-specific design thickness rules; do not apply a universal 0.93t factor.
Respect minimum thickness, corner radii and corrosion/holes/remaining section.
For RHS ideal sharp-corner formulas, identify APPROXIMATE geometry; no issued design using unverified approximation if capacity depends on it.
Examples for catalog demonstration only:
STKR400: Fy 245 MPa, Fu 400 MPa; STKR490: Fy 325 MPa, Fu 490 MPa, subject to product confirmation.
For C channels include orientation, load eccentricity, torsion, lateral restraint and web crippling at ties/supports.
Paired members must have a declared load-sharing/connector model. Do not always double I or divide load by two.
Geometric combination of two members does not prove composite structural action.

5.3 Through-ties and corner clamps
Certified form-tie sets: manufacturer allowable working load, ultimate-tested load,
safety factor already applied, nominal/core/thread geometry, nut/plate compatibility and condition limits.
Custom rod branch: material, gross/net/thread tensile area, manufacturing method,
thread pitch/profile/engagement, nuts, welds/couplers, bearing plates and validated end connection.
RB normally means smooth round SR24, not SD40. DB SD40 means deformed bar.
Illustrative material entries only: SR24 Fy235/Fu385 MPa; SD40 Fy390/Fu560 MPa.
Do not use rebar diameter as threaded stress area.
Do not give a custom threaded rebar rod certified capacity from 0.6FyAg.
Actual rolling/cutting/machining/welding can alter section/properties; require supporting evidence.
Check yielding, rupture, thread stripping, connection resistance and accessory safety.
Do not divide a manufacturer's already allowable working load by the same factor again.
For ACI accessory checks, verified minimum form-tie factor 2.0 is relative to ultimate assembly capacity/unfactored load; higher manufacturer factors govern.
An AISC ASD factor 1.67 and an accessory ultimate factor 2.0 are different checks, not automatic consecutive divisors.
External column corner clamp geometry and force model must be explicitly defined and validated.

5.4 "34 mm steel prop" — MUST REMAIN UNRESOLVED UNTIL IDENTIFIED
Record the owner's initial description: steel bracing member size 34 mm.
Do not assume solid bar, 34 mm outside-diameter tube, nominal pipe size or telescopic prop.
Require type, OD/actual dimensions, wall thickness, grade, total/effective length,
extension length, overlap/pin/thread details, end restraints, attachment geometry,
manufacturer rating or verified buckling model, tension/compression capability and condition.
Provide editable input for these fields. When unknown, bracing remains INCOMPLETE and issue is blocked.
A gravity-only acrow prop is not automatically a tension-capable push-pull brace.
No silent default thickness such as 2.0/2.3 mm.

5.5 Connections and supports
Plates, bolts, welds, anchors, base shoes, supporting slab/soil, work platforms:
material grades, actual geometry, relevant ratings/design methods,
concrete fc'/thickness/cracked-state/age, edge distance, embedment,
soil allowable bearing where applicable, and evidence.
Do not automatically treat lean-concrete blinding as an adequate anchor foundation.

6. PRESSURE ENGINE AND LOAD CASES
6.1 Implement a verified hydrostatic top-pour baseline:
At each pour stage, p(z)=γc z, where z is depth below the CURRENT fresh-concrete surface.
Pressure on not-yet-filled portions is zero; analyze all relevant stages and envelope member demand.
Integrate actual pressure diagrams; provide exact piecewise-linear load evaluation.
If using a conservative maximum uniform pressure on a component span, label the approximation explicitly and show the actual diagram too.
Do not silently assume pressure vanishes after a guessed setting time.
Reduced ACI-pressure methods require full applicable inputs and verified branch conditions.
For SCC without qualified pressure-reduction evidence, use hydrostatic baseline.
Bottom pumping/external vibration/expansive concrete require special validated pressure cases. An unimplemented special case is UNSUPPORTED, not automatically hydrostatic.
Pump-from-base implementation must reflect verified surge requirements and pressure monitoring limits, not a universal guarantee that 1.25γH caps actual pump pressure.
Keep erection wind and gravity loads distinct from internal pressure.
Opposing-face pressure balance does not eliminate local outward panel/yoke loads.
Permanent rebar cage is not a support or brace unless specifically designed and accepted as such.

6.2 Load stages
Erection empty form, partial fill, full fill, platforms/equipment,
wind in +/- X/Y, stripping and panel lifting where a supported method exists.
Temporary panel lifting requires lifting points/capacity/geometry; otherwise identify OUT OF SCOPE.
Construction wind inputs need documented project basis; no invented Rayong wind speed.
Pressure-only "PASS" is a component result, never a whole-system PASS.

7. MEMBER ANALYSIS AND FOOTING CALCULATIONS
Build a pure typed domain engine independent of React/Firebase. Support actual member/support coordinates, overhangs, load patches and pressure breakpoints.
A practical initial verified analysis set:
- Simply supported beams under uniform/linear/piecewise-linear loading.
- Declared cantilever end segments and validated continuous-beam models as separately registered capabilities.
- If a real layout is continuous, do not use simple-span reactions as exact multi-support reactions.
- If using a deliberately conservative isolated-span idealization, identify which checks it bounds; verify reactions/connections separately.
- Solve stiffness/matrix models robustly with unit-scaled tolerances, instability/singular-model detection and equilibrium checks. Never return a plausible zero for a mechanism.
No black-box finite element method without benchmarks and method scope.

Footing sequence:
1. Internal concrete dimensions and pour cases.
2. Pressure envelope.
3. Plywood per direction/support arrangement: bending, rolling shear, bearing, deflection.
4. Studs: mapped pressure tributary strip, span demands/reactions, steel resistance and deflection.
5. Double walers: actual stud reactions at coordinates, actual tie supports, overhangs and splices.
6. Ties: governing waler reactions from BOTH faces; one continuous tie carries axial tension, not twice the same face force.
7. Tie extension, end connections, plates/nuts, local steel bearing/crippling.
8. Corners, seams and panel joints.
9. Bracing and stability/anchors/supports.
10. Combined face movement and layout interference.
11. Candidate comparison, schedules, drawings and report.

Benchmark formulas for a simply supported UNIFORM-load beam only:
Mmax=wL²/8; Vmax=wL/2; δmax=5wL⁴/(384EI).
For these equations, w N/mm, L mm, E N/mm² and I mm⁴.
Do not apply these coefficients to unequal spans, triangular load, cantilevers or moment-resisting corners.
All mapped forces must conserve integrated pressure resultant and moment, including edge tributary regions. Do not discard last bays.
Analyze every boundary face and its local tie system separately; rectangular X/Y systems are special cases. Tie lengths, reactions and capacities can differ. Confirm complete edge coverage for polygons, including notch faces.
Check real geometric paths of orthogonal tie sleeves, intersections, rebar/concrete-cover conflicts and installation access. Do not hide rod collisions in drawings.
Rebar geometry is optional project input for clash depiction; do not design permanent reinforcement or invent real bar layouts.

8. COLUMN CALCULATIONS
Implement confirmed section polygons with extrusion height and pressure stages, face plywood/studs, yoke/frame levels, panel splices, global stability and bracing. Section2C governs nonrectangular topology; apply width/depth shortcuts only to true rectangular cases.
For external yokes, compute corner forces using:
(a) a certified manufacturer's system layout/rating within its validity limits; OR
(b) a validated closed-frame/joint model with actual connection geometry, eccentricities and restraint assumptions.
Do not pretend a 2D rigid closed-frame model represents a pin/sliding/overlapping corner clamp automatically.
For a custom system, provide a supported connection configuration with independently verified analytical benchmarks. Otherwise expose face demands and leave corner/system checks INCOMPLETE.
Check yoke biaxial/combined demands, shear/torsion where relevant, double-member load sharing, external clamp rods, corner plates and joints.
Support actual top/bottom edge offsets and variable yoke spacing; number of rings alone is insufficient.
Column 1×1×8 m must have full-height stability checks with actual brace attachment levels and panel-joint stiffness.
Evaluate out-of-plumb, brace-induced local forces, second-order effects where required by adopted method, and both lateral directions.
Check work platform/independent access tower separately. A tower is not automatically formwork bracing.
Upper brace connections must connect to structural members with verified capacity, not just plywood.
No global approval of an 8 m column with only pressure/yoke checks.

9. DESIGN PROPOSAL AND CHECK MODE

User confirmation of a candidate is not an engineering approval.
